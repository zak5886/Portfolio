Common Assembly Patterns

x86 ASM
; === FUNCTION PROLOGUE / EPILOGUE ===
push rbp              ; Save caller's base pointer
mov rbp, rsp          ; Set base pointer to current stack
sub rsp, 0x40         ; Allocate local variables (64 bytes)
; ... function body ...
mov rsp, rbp          ; Restore stack pointer
pop rbp               ; Restore base pointer
ret                   ; Return to caller

; === CALLING CONVENTION (Windows x64) ===
; Arguments: RCX, RDX, R8, R9, then stack
; Return value: RAX
; Callee-saved: RBX, RSI, RDI, RBP, R12-R15
; Shadow space: 32 bytes (0x20) always allocated on stack

; === XOR DECRYPT LOOP (common in malware) ===
lea  rsi, [encrypted_data]  ; RSI = pointer to encrypted buffer
mov  rcx, 0x100             ; RCX = loop counter (256 bytes)
mov  bl, 0x42               ; BL  = XOR key
decrypt_loop:
  xor  byte ptr [rsi], bl   ; Decrypt byte
  inc  rsi                  ; Advance pointer
  loop decrypt_loop         ; Dec RCX, jump if not zero

; === CONDITIONAL JUMP REFERENCE ===
je  / jz   → Jump if Equal (ZF=1)
jne / jnz  → Jump if Not Equal (ZF=0)
jl  / jnge → Jump if Less (signed)
jg  / jnle → Jump if Greater (signed)
jb  / jnae → Jump if Below (unsigned)
ja  / jnbe → Jump if Above (unsigned)
jmp        → Unconditional jump
call       → Push RIP, jump (CALL = PUSH+JMP)
ret        → Pop RIP, jump back

; === SUSPICIOUS SHELLCODE PATTERNS ===
call $+5             ; Get EIP (position-independent code)
pop  eax             ; EAX now = address of 'pop eax'

; GetProcAddress dynamic API resolution pattern:
mov  eax, [fs:0x30]  ; PEB (Process Environment Block)
mov  eax, [eax+0x0C] ; PEB_LDR_DATA
mov  eax, [eax+0x14] ; InMemoryOrderModuleList
; ... walk module list to find kernel32.dll by hash

📦Unpacking & DeobfuscationRE

Generic Unpacking Methodology

1
Identify Packer
Use Detect-It-Easy (DIE) or PEiD. High section entropy (>7.0) = packed. Small import table = packed. Suspicious section names (.UPX0, .nsp0, CODE).
2
Try Automatic Unpackers
UPX: upx -d sample.exe. For others: try UnpacMe (online), unipacker, or PE-bear. Many common packers have known unpackers.
3
Manual Unpack — OEP Hunt
Run in x64dbg. The packer stub decrypts/decompresses payload then jumps to Original Entry Point (OEP). Break on OEP, dump process.
4
Dump & Fix IAT
Use Scylla (in x64dbg) to dump process at OEP. Fix Import Address Table (IAT). Rebuild PE — now fully unpacked for static analysis.
5
Analyze Unpacked Binary
Load clean dump in IDA/Ghidra. Perform full static analysis on the deobfuscated payload.

# Method 1: Hardware breakpoint on memory write then execute
# 1. Run to packed entry point (EP)
# 2. Identify unpacking loop writing to memory region
# 3. Set hardware BP on write to unpacking destination
# 4. Run — breaks when packer writes to OEP region

# 1. Run to packed EP
# 2. Execute PUSHAD (saves all registers to stack)

import struct

# XOR decode with rotating key
def xor_rotating(data, key):
    result = bytearray()
    for i, byte in enumerate(data):
        result.append(byte ^ key[i % len(key)])
    return bytes(result)

# RC4 stream cipher (common in malware configs)
def rc4(key, data):
    S = list(range(256))
    j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) % 256
        S[i], S[j] = S[j], S[i]
    i = j = 0
    result = bytearray()
    for byte in data:
        i = (i + 1) % 256
        j = (j + S[i]) % 256
        S[i], S[j] = S[j], S[i]
        result.append(byte ^ S[(S[i] + S[j]) % 256])
    return bytes(result)

# Base64 variants (malware uses custom alphabets)
import base64
def custom_b64_decode(data, custom_alphabet):
    standard = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"
    translation = str.maketrans(custom_alphabet, standard)
    return base64.b64decode(data.translate(translation))

0️⃣Zero-Day HandlingCRITICAL

🔴 Zero-day handling requires extreme operational security. Limit knowledge to essential personnel only until vendor patch is available.

Zero-Day Response Protocol

1
Confirm Zero-Day Status
Verify: no CVE assigned, no public PoC, no vendor acknowledgment. Check NVD, vendor security advisories, ExploitDB, FullDisclosure, and researcher Twitter/X. Is this truly novel?
2
Characterize the Vulnerability
RE the exploit. Identify: affected component, vulnerability class, authentication requirement, exploit reliability, scope (local/remote). Write technical description.
3
Assess Immediate Risk
Is this actively being exploited against you? Against others? What is blast radius if exploited? Apply emergency mitigations: disable affected service, WAF rule, network segmentation.
4
Responsible Disclosure
Notify vendor via their security disclosure process (security@vendor.com or HackerOne/Bugcrowd). Include: full technical details, PoC (if you have one), your timeline. Standard disclosure window: 90 days (Google Project Zero policy).
5
Create Proprietary Detection
Write YARA/Sigma/SIEM rules to detect exploitation attempts. Keep rules internal until patch available to avoid tipping off attackers about detection capability.
6
Post-Patch: Public Disclosure
After vendor patches: coordinate public disclosure. Share IOCs, detection rules with community. Write blog/report to improve industry-wide detection.

Detection Engineering Maturity Levels

Level 1 — Reactive
IOC-based detections only. Known malware hashes, IP blocklists. High FP rate. Completely blind to novel threats.
Level 2 — Behavioral
TTP-based detection. SIGMA rules, anomaly detection, UEBA. Catches novel malware using known techniques.
Level 3 — Predictive
ML-based anomaly + threat modeling. Hunting program. Detection coverage mapped to ATT&CK. Purple team validation.

SIEM Architecture Principles

  • Log everything that matters: Endpoint (Sysmon), network (NetFlow/PCAP), auth (Windows Sec/Linux syslog), cloud (CloudTrail/Azure Monitor), email, proxy/DNS
  • Centralize, don't silo: All logs to one SIEM for correlation. Cross-source correlation = detection capability
  • Retention: Hot storage 90 days minimum. Cold/archive 1-3 years (compliance + breach investigation)
  • Coverage gaps: Regularly audit what is NOT being logged. Attacker-blind-spots = detection-blind-spots
  • Alert quality over quantity: 95%+ true positive rate target. Tune aggressively. Analyst fatigue = missed incidents
