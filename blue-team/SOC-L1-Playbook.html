👤L1 Roles & ResponsibilitiesSCOPE

Primary Responsibilities

  • Monitor SIEM dashboards and alert queues during shift
  • Perform initial triage on all incoming alerts within SLA
  • Classify alerts by severity and type
  • Investigate alerts using available tools and runbooks
  • Document findings in ticketing system (ServiceNow / Jira)
  • Escalate confirmed or suspected incidents to L2
  • Execute approved containment actions (block IP, disable account, isolate host)
  • Complete shift handover report with open/pending items
  • Tune out known false positives with proper documentation
  • Keep threat intel feeds and IOC lists updated

L1 Does NOT Do

❌ Deep malware reverse engineering (→ L2/L3)
❌ Hunt for unknown threats proactively (→ L2)
❌ Modify firewall/network policies without approval
❌ Communicate breach status to management/public (→ IR Lead)
❌ Perform forensic disk imaging (→ L2/L3)

📋Alert TriagePROCESS

5-Question Triage Framework

1
WHAT triggered the alert?
Identify the rule/signature. Understand what behavior it detects. Read the rule description carefully.
2
WHO is involved?
Identify user, hostname, IP. Is it a privileged account? Is it a known/critical asset? Check CMDB/AD.
3
WHEN did it happen?
Business hours or off-hours? First time or repeated? Is there a change window? Check ticket history.
4
WHERE is it going / coming from?
Source/destination IPs. Internal or external? Known bad IP/domain? Check threat intel. Geo-location.
5
HOW severe is it?
Apply severity matrix. Is there corroborating evidence? Assign severity and decide: close, monitor, or escalate.

Quick Triage Checklist

  • Acknowledge alert in SIEM within SLA window
  • Read full alert details — don't just read the title
  • Look up source/destination IPs in threat intel
  • Check if user/host has related alerts in last 24–72hrs
  • Search SIEM for related events around same timeframe
  • Check if change ticket exists (authorized activity?)
  • Assign severity based on matrix
  • Create ticket with full details and initial findings
  • Escalate or close with documented reasoning

🔄Triage WorkflowSOP

Standard Operating Procedure

1
Alert Received in SIEM
Alert appears in queue. Acknowledge within SLA. Assign to yourself in ticketing system.
2
Initial Context Gathering
Pull full event logs. Identify: user, host, IP, time, process, command line. Note all IoCs.
3
Threat Intel Enrichment
Look up IPs/domains/hashes in VirusTotal, AbuseIPDB, MISP. Check internal blocklists. Document all findings.
4
Correlation Search
Search SIEM for related events: same user, same host, same IP, ±2 hours. Look for attack chain patterns.
5
Severity Assessment
Apply severity matrix. Consider asset criticality, user privilege level, and corroborating evidence.
6
Decision Point
True Positive → Create/update incident ticket, escalate if needed.
False Positive → Close with documentation, consider tuning request.
7
Document & Close or Escalate
Every action documented with timestamp. If escalating: hand off ticket with full context to L2.

🔶Splunk SPL QueriesSIEM

Splunk EnterpriseSplunk CloudSIEM

Authentication & Account Activity

SPL
# Failed logins — detect brute force
index=windows EventCode=4625
| stats count by src_ip, user, dest
| where count > 10
| sort -count

# Successful login after many failures (brute force success)
index=windows (EventCode=4625 OR EventCode=4624)
| stats count(eval(EventCode=4625)) as failures, count(eval(EventCode=4624)) as successes by user, src_ip
| where failures > 5 AND successes > 0

# Impossible travel (same user, different geos, short time)
index=auth user=* src_ip=*
| iplocation src_ip
| stats values(Country) as countries, dc(Country) as country_count, min(_time) as first, max(_time) as last by user
| where country_count > 1 AND (last - first) < 3600

Malware & Endpoint

SPL
# Suspicious PowerShell execution
index=windows EventCode=4104 OR EventCode=4688
| search (ScriptBlockText="*Invoke-Expression*" OR ScriptBlockText="*IEX*" OR ScriptBlockText="*-EncodedCommand*" OR ScriptBlockText="*DownloadString*")
| table _time, host, user, ScriptBlockText

# Process created with encoded command
index=windows EventCode=4688
| search CommandLine="*-enc*" OR CommandLine="*-EncodedCommand*"
| table _time, host, user, ParentProcessName, CommandLine

# LSASS access (credential dumping)
index=windows EventCode=10 TargetImage="*lsass.exe"
| where GrantedAccess="0x1FFFFF" OR GrantedAccess="0x1010"
| table _time, host, SourceImage, TargetImage, GrantedAccess

Network & C2 Detection

SPL
# Beaconing — regular interval connections (C2)
index=network
| eval interval = round((_time - lag(_time,1,0) over (src_ip, dest_ip)),0)
| stats stdev(interval) as jitter, count by src_ip, dest_ip, dest_port
| where jitter < 10 AND count > 50
| sort -count

# DNS requests to newly registered domains
index=dns query_type=A
| lookup newly_registered_domains domain as query OUTPUT is_new
| where is_new="true"
| stats count by src_ip, query

# Large data transfer to external IP
index=network bytes_out > 100000000
| iplocation dest_ip
| where Country != "YourCountry"
| stats sum(bytes_out) as total_bytes by src_ip, dest_ip, Country
| sort -total_bytes

Threat Hunting Searches

SPL
# Search for specific IOC (IP)
index=* src_ip="1.2.3.4" OR dest_ip="1.2.3.4"
| table _time, index, sourcetype, src_ip, dest_ip, user, host

# Search for known bad hash
index=* (md5="BADHASH" OR sha256="BADHASH")
| table _time, host, user, file_path, file_name, hash

# Lateral movement via PsExec
index=windows (EventCode=7045 OR EventCode=4697)
| search ServiceFileName="*PSEXESVC*" OR ServiceFileName="*psexec*"
| table _time, host, user, ServiceName, ServiceFileName

Authentication Queries

KQL
// Failed sign-ins — brute force detection
SigninLogs
| where TimeGenerated > ago(1h)
| where ResultType != 0  // Failed
| summarize FailureCount = count() by UserPrincipalName, IPAddress, AppDisplayName
| where FailureCount > 10
| order by FailureCount desc

// Successful login after failures (account compromise)
let failures = SigninLogs
    | where ResultType != 0
    | summarize FailCount = count() by UserPrincipalName, IPAddress;
SigninLogs
| where ResultType == 0
| join kind=inner failures on UserPrincipalName
| where FailCount > 5
| project TimeGenerated, UserPrincipalName, IPAddress, Location, AppDisplayName, FailCount

// MFA bypass / disabled
SigninLogs
| where AuthenticationRequirement == "singleFactorAuthentication"
| where ResultType == 0
| where UserPrincipalName !in (known_exclusions)
| project TimeGenerated, UserPrincipalName, IPAddress, Location, ClientAppUsed

Endpoint & Process

KQL
// Suspicious PowerShell
DeviceProcessEvents
| where TimeGenerated > ago(24h)
| where FileName =~ "powershell.exe"
| where ProcessCommandLine has_any ("-EncodedCommand", "-enc", "IEX", "Invoke-Expression", "DownloadString", "bypass")
| project TimeGenerated, DeviceName, AccountName, ProcessCommandLine

// LSASS memory access
DeviceEvents
| where ActionType == "OpenProcessApiCall"
| where FileName =~ "lsass.exe"
| where InitiatingProcessFileName !in~ ("MsMpEng.exe","csrss.exe","wininit.exe")
| project TimeGenerated, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine

// New scheduled task
DeviceEvents
| where ActionType == "ScheduledTaskCreated"
| where InitiatingProcessAccountName != "SYSTEM"
| project TimeGenerated, DeviceName, InitiatingProcessAccountName, AdditionalFields

Network & Threat Hunting

KQL
// Connections to threat intel IOCs
DeviceNetworkEvents
| where TimeGenerated > ago(24h)
| join kind=inner (ThreatIntelligenceIndicator | where Active == true) on $left.RemoteIP == $right.NetworkIP
| project TimeGenerated, DeviceName, InitiatingProcessFileName, RemoteIP, RemoteUrl, ThreatType, ConfidenceScore

// DNS queries to suspicious domains
DnsEvents
| where TimeGenerated > ago(1h)
| where Name has_any ("dyn.com","no-ip.org","ngrok.io","pastebin.com")
| project TimeGenerated, Computer, ClientIP, Name, QueryType

// Anomalous outbound data volume
DeviceNetworkEvents
| where TimeGenerated > ago(1h)
| where RemoteIPType == "Public"
| summarize TotalBytes = sum(SentBytes) by DeviceName, RemoteIP
| where TotalBytes > 50000000
| order by TotalBytes desc

EQL (Event Query Language) — Threat Hunting

EQL
# Sequence: PowerShell spawning network connection (C2 pattern)
sequence by host.name [
  process where process.name == "powershell.exe"
    and process.command_line like~ "*DownloadString*"
] [
  network where destination.port in (80, 443, 4444, 8080)
    and process.name == "powershell.exe"
]

# Credential dumping via ProcDump
process where process.name == "procdump*.exe"
  and process.args like~ "*lsass*"

# Suspicious parent-child (Office spawning PowerShell)
process where process.parent.name in ("winword.exe","excel.exe","outlook.exe")
  and process.name in ("powershell.exe","cmd.exe","wscript.exe","cscript.exe")

🟣IBM QRadar AQLSIEM

IBM QRadarAQLQRadar SOAR

AQL Queries

AQL
-- Brute force: Multiple failed logins
SELECT sourceip, username, COUNT(*) as failures
FROM events
WHERE LOGSOURCETYPENAME(devicetype) = 'Microsoft Windows Security Event Log'
  AND qid = 28250006  -- Windows EventID 4625
  AND LAST 1 HOURS
GROUP BY sourceip, username
HAVING failures > 10
ORDER BY failures DESC

-- Successful login after failures
SELECT sourceip, username, eventcount
FROM events
WHERE qid IN (28250006, 28250004)  -- 4625=fail, 4624=success
  AND LAST 4 HOURS
GROUP BY sourceip, username
HAVING SUM(CASE WHEN qid=28250006 THEN 1 ELSE 0 END) > 5
   AND SUM(CASE WHEN qid=28250004 THEN 1 ELSE 0 END) > 0
AQL
-- Suspicious PowerShell (Sysmon EventID 1)
SELECT sourceip, username, "Process CommandLine"
FROM events
WHERE LOGSOURCETYPENAME(devicetype) = 'Microsoft Windows Security Event Log'
  AND qid = 28250001  -- Sysmon Process Create
  AND "Process Name" ILIKE '%powershell%'
  AND ("Process CommandLine" ILIKE '%enc%' OR "Process CommandLine" ILIKE '%IEX%')
  AND LAST 24 HOURS

-- Large outbound transfer
SELECT sourceip, destinationip, destinationport, SUM(destinationbytes) as bytes_out
FROM flows
WHERE flowdirection = 'R'   -- Outbound
  AND destinationip NOT IN (REFERENCESET('Internal_Ranges'))
  AND LAST 1 HOURS
GROUP BY sourceip, destinationip, destinationport
HAVING bytes_out > 100000000
ORDER BY bytes_out DESC

🎣Phishing InvestigationPLAYBOOK

⚠ Do NOT click links in suspicious emails directly. Use a sandboxed browser or URL sandbox tool.

Phishing Triage Checklist

  • Identify the reporting user and affected mailbox
  • Retrieve email headers (From, Reply-To, Return-Path, Received)
  • Check sender domain/IP reputation (MXToolbox, VirusTotal, AbuseIPDB)
  • Examine email body for urgency language, impersonation, suspicious links
  • Extract and analyze all URLs (URLScan.io, VirusTotal, Joe Sandbox)
  • Extract and hash any attachments — check hashes in VirusTotal
  • Check SPF / DKIM / DMARC pass/fail in headers
  • Search email gateway logs: how many users received this email?
  • Check if any users clicked the link (proxy/web filter logs)
  • Check if any users entered credentials (identity/auth logs)

Email Header Analysis

BASH
# Key headers to check:
From:          # Display name (can be spoofed)
Return-Path:   # Actual sender - should match From
Reply-To:      # Where replies go - red flag if different
Received:      # Mail server hops - read bottom to top
X-Originating-IP: # Sending IP
Authentication-Results: # SPF/DKIM/DMARC results

# SPF result meanings:
pass    → Sender authorized
fail    → Sender NOT authorized (suspicious)
softfail → Likely unauthorized (treat as suspicious)
neutral  → No policy defined
none     → No SPF record (suspicious for known companies)

# DKIM: Check "dkim=pass" — verifies email wasn't tampered
# DMARC: Check "dmarc=pass" — organizational policy enforcement

🦠Malware Analysis BasicsPLAYBOOK

L1 role: Triage and contain. Deep analysis is L2/L3. Your job is to identify, classify, and contain.

Initial Malware Triage

  • Get file name, path, and hash (MD5, SHA256)
  • Check hash in VirusTotal — note detection ratio and family name
  • Note how it was introduced: email attachment, web download, USB, lateral movement?
  • Check if AV quarantined it — if not, that's urgent
  • Look for related process creation events before/after
  • Check for persistence indicators: scheduled tasks, registry run keys, new services
  • Check for network connections from the affected host after infection time
  • Check for lateral movement: new auth events from that host

Endpoint Investigation Steps

1
Identify the Process
Process name, full path, PID, parent process, command line arguments, user context.
2
Check Process Legitimacy
Is it running from expected location? (e.g., svchost should be in System32). Hash the binary → VirusTotal.
3
Network Activity
What network connections did this process make? To what IPs/domains? Check reputation.
4
File System Activity
Files created/modified/deleted by this process. New files in temp folders, AppData, or system directories.
5
Persistence Check
New scheduled tasks, registry run keys, new services, startup folder entries around same timeframe.

🚒Incident Response ProceduresIR

IR Lifecycle (L1 Touchpoints)

1
Detection & Analysis
Alert fires in SIEM. L1 triages, enriches with threat intel, determines True Positive. Creates incident ticket.
2
Notification & Escalation
L1 notifies L2 per severity SLA. Provides full context, IOCs, and timeline. PagerDuty for P1/P2.
3
Containment (L1 Actions)
L1 executes approved containment: block IP in firewall, isolate endpoint via EDR, disable compromised account.
4
Evidence Preservation
L1 preserves logs: export SIEM events, note raw log locations, do NOT alter or delete. Screenshot everything.
5
Continued Monitoring
Monitor for spread to other systems. Watch for new alerts from affected user/host. Update ticket with findings.
6
Hand-off to L2
Full ticket with complete timeline, IOCs, actions taken, and recommendations. Brief L2 verbally if critical.

Account Containment

POWERSHELL
# Disable AD user account
Disable-ADAccount -Identity "compromised.user"

# Force password reset at next login
Set-ADUser -Identity "compromised.user" -ChangePasswordAtLogon $true

# Remove from all groups (use carefully — document first!)
$groups = (Get-ADUser "compromised.user" -Properties MemberOf).MemberOf
$groups | Remove-ADGroupMember -Members "compromised.user" -Confirm:$false

# Azure AD — Revoke all refresh tokens (via Azure AD PowerShell)
Revoke-AzureADUserAllRefreshToken -ObjectId "user@company.com"
